# بناء لإدارة النقل والعمليات

تطبيق عربي RTL مبني بـ React وSupabase لإدارة ورديات النقل، التوصيلات، حركة الخامات، المصروفات، العهد النقدية، حسابات العملاء، والتقارير.

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env` وضع رابط مشروع Supabase والمفتاح العام `anon` أو `publishable` فقط.
2. ثبّت الحزم: `npm install`.
3. شغّل الاختبارات: `npm test`.
4. شغّل التطبيق: `npm run dev`.

## إعداد Supabase

طبّق ملفات SQL الموجودة في `supabase/migrations` بالترتيب. الملفات تنشئ الجداول والسياسات وعمليات RPC والتخزين الخاص. راجع أسماء الجداول قبل التنفيذ إذا كان المشروع يحتوي على مخطط قائم.

أنشئ المستخدمين من Supabase Auth بأرقام موبايل مصرية بصيغة دولية مثل `+201012345678` وكلمة مرور. التطبيق يقبل إدخال `01012345678` ويحوّله تلقائيًا للصيغة الدولية. بعد إنشاء أول مستخدم، عيّنه كمالك من SQL Editor مع استبدال UUID:

```sql
insert into public.user_roles (user_id, role_id)
select 'USER_UUID'::uuid, id from public.roles where name = 'owner';

insert into public.employees (profile_id, name)
select id, name from public.profiles where id = 'USER_UUID'::uuid
on conflict (profile_id) do nothing;
```

عطّل التسجيل العام في إعدادات Auth. لا تضع مفتاح `service_role` في التطبيق أو ملفات البيئة الأمامية. اضبط `APP_ORIGIN` في Edge Function على أصل النشر إذا قررت استخدام بوابة `operations`؛ الواجهة الحالية تستدعي RPC المحمي مباشرة.

## قواعد مالية

- أرصدة العهد تُحسب من دفتر حركات غير قابل للتعديل أو الحذف.
- العكس المالي يتم بقيد عكسي، ولا يتم تعديل القيد الأصلي.
- التحويل بين موظفين لا يؤثر في الرصيد حتى يؤكد المستلم.
- إغلاق الوردية يقارن النقدية المعدودة بالرصيد المتوقع، والفرق يحتاج اعتماد محاسب أو مالك.
- الفاتورة والتحصيل والعهدة والمصروف وحركة الخامة سجلات منفصلة.
- العمليات المرسلة دون اتصال تبقى معلّقة، ولا تعرض كتأكيد مالي قبل قبول الخادم.

## التحقق

`npm run check` يشغّل اختبارات الحسابات وسياسات الصلاحية والمعاملات على PostgreSQL محلي، ثم يبني نسخة الإنتاج.
